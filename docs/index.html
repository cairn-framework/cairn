Your architecture is only true if something can prove it wrong.

Cairn is the log book for your codebase. Your coding agent writes down what the system is meant to be. Cairn checks that against the code on every commit, then signs it off, defers it, or grounds the merge.

Set it up with your agent Read the spec

A blueprint that disagrees with the code is reported as a finding, exactly like wrong code is. That is the whole trick. Documentation you cannot falsify is documentation you cannot trust.

02

Three kinds of wrong, kept apart on purpose.

A workshop does not have one word for a problem. It has a tag that says what the problem stops, and a line for the person who signed it. Cairn works the same way. Calling everything a warning is how a good plan quietly rots.

Unserviceable

Structural error

The record contradicts itself: the same node ID declared twice, an edge pointing at a node that does not exist, an artefact naming a node nobody declared, or a cycle in the dependency graph. Nothing built on a record like that can be trusted.

Stops the scan

Unserviceable

Interface contradiction

The contract says one thing and the code does another. The interface hash moved and nobody updated the promise. This is drift caught in the act, before your agent ships the version that breaks everything above it.

Stops the merge

Deferred defect

Rationale tension

Two decisions are fighting, or the evidence behind one no longer holds. The code still builds and the promises still hold, but the story has drifted. Raised and tracked, so you can settle it next time you are in there anyway.

Stops nothing, books a review

Serviceable

Synced

The declaration and the code agree. This is not a green tick on a dashboard. It is a statement that something checked, and that the check can be run again by anyone who does not believe it.

Signed by cairn scan

Two of those tags are red on purpose. Both block, and they differ in what they block. A broken record fails the scan outright. A contract the code has outgrown fails the merge. Collapsing them into one severity would tell you something is wrong without telling you what to do about it.

04

Evidence goes in. Authority comes out. A decision is where they meet.

An aircraft is legal to fly because a chain of paper says so, and because one named certificate reads that evidence and issues the permission. Cairn has the same shape, and it is the part that answers "why is it like this" a year from now.

Provenance chain · evidence in
source

The raw material. A paper, a benchmark, a thread, a spec you had to read.

research

What you made of it. Sources cited, so the reasoning can be re-walked.

Certificate Decision

Reads the evidence. Issues the rule. Nothing downstream is allowed to appear from nowhere.

dec.code-reconciliation
Authority chain · rules out
blueprint

The shape of the system. Which parts exist and how they depend on each other.

contract

The promise a part makes. Broken quietly, this is what grounds a merge.

code

What is actually on disk. The only thing that gets to be the last word.

Ask any node why it is shaped the way it is and you get the trail back, not a guess: cairn rationale cairn.reconcile returns every accepted decision that binds it, each with the research and sources behind it. Decisions your team argued about in a thread six months ago now live next to the code they constrain.

05

Code is the first thing it is rated to check.

A reconciler answers one question: for a declared part, what is really there? Cairn's core does not care which one you plug in. Anywhere "what we said" has to stay honest with "what is", the same machine applies. Only the first is certified today.

Certified

Source code

Node paths, interface hashes, contract files. Rust, TypeScript, Python, and Go, checked against what the blueprint said they would be.

Not yet certified

Research projects

Experiments, methods, and claims as typed records. Check the claims in the draft against the evidence meant to support them.

Not yet certified

Team design

Teams, charters, and ownership. Check the org chart you drew against who is actually responsible this quarter.

Not yet certified

Parts lists

Components, suppliers, and sign-offs. Check the bill of materials against the real audit, before the inspector does.

06

Release to service.

Your first scan writes map.md and map.json for humans reading a diff, and from the next prompt your agents orient with cairn context, cairn get, and cairn neighbourhood instead of re-reading your source tree. Cairn runs locally. Nothing leaves your machine.

Fastest path · paste into your coding agent
Read https://raw.githubusercontent.com/cairn-framework/cairn/main/docs/agent-setup.md and follow it to set up Cairn in this repo.

Your agent installs the CLI, works out whether this is a new or existing project, drafts the map with you, wires itself in, and arms the gate.

Prefer to drive it yourself
Installshell
$ curl --proto '=https' --tlsv1.2 -LsSf \
    https://github.com/cairn-framework/cairn/releases/latest/download/cairn-installer.sh | sh

$ cairn init --wire     # scaffold, install the agent pack, wire it in
$ cairn scan           # reconcile, write the map
$ cairn hook all       # the gate: wire into pre-commit or CI

The clean exit guarantee. Try it on a branch. If you hate it, run cairn pack uninstall to take the agent pack back out, then delete cairn.blueprint, cairn.config.yaml, .cairn/, the generated map files, and the empty meta/ folders the scaffold made. Then take Cairn's block back out of your agent instructions file, or delete that file if Cairn created it. Your repository is exactly what it was. Already have a codebase? cairn init --from-code drafts the whole map from your source tree as a change proposal you review before anything lands.
