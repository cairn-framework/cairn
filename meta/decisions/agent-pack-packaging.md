# Agent-pack packaging: one canonical source, deterministic per-harness adapters

## Status and ratification

The owner ratified this decision on 2026-07-13. The direction (one canonical
harness-neutral source plus a deterministic packager emitting per-harness
formats, generic-by-default with a repo-bindings seam) and the eight-point
contract below, refined by the cross-ecosystem survey
(res.agent-pack-packaging-survey), are ratified as written. No code exists yet;
implementation is tracked by todo.agent-pack-implementation.

## Decision (the contract)

1. **One canonical source.** A harness-neutral product-pack source directory
   at repo root (working name `tools/agent-pack/`) holds skill bodies,
   AGENTS.md wire-block fragments, hook definitions, and a pack manifest
   declaring bundle version, skill list, and one adapter row per harness.
   Maintainers edit only this source.
2. **Adapters are pure functions** from canonical pack to emitted file sets.
   Structural per-harness differences (paths, discovery rules, hook variants)
   live in the adapter table as data; prose fragments are shared only when
   genuinely identical. Adapter rows for unverified harnesses are contracts,
   not facts: an adapter ships only after validation in its live harness
   (Claude Code first, OMP second).
3. **Rendered artefacts are generated, never hand-edited.** This repo's own
   `.claude/skills/` cairn-* pack becomes rendered output, regenerated by a
   build-time renderer (dev-only, not shipped in the user CLI) and compiled
   into the binary via `include_str!` as today. A byte-for-byte check guards
   renderer drift, extending the repo's existing `wire_format_snapshots`
   golden discipline.
4. **One install verb, no per-harness fan-out.** A single pack lifecycle
   command family (`install | update | status | uninstall`) with a
   `--harness <name>` selector and auto-detection. The survey's graphify
   precedent shows the duplication anti-pattern this avoids (generic verb plus
   ~22 per-platform command families). `init --wire` remains the first-run
   seam and delegates to the pack installer.
5. **Manifest as ownership ledger.** Install state lives in one manifest in
   the target repo recording schema version, installed CLI version, installed
   bundle version, and per-file content hashes. The packager may write,
   update, or retire ONLY files listed in the manifest at a matching hash.
   Hand-authored skills and existing AGENTS/CLAUDE content are never
   overwritten or deleted; divergence is reported.
6. **Drift semantics: warn, never block.** Every cairn invocation may cheaply
   compare versions; mismatch surfaces as an info-level finding with an
   explicit update verb. Per file, three-way handling: pristine (hash match)
   refreshes, modified reports and is never overwritten, missing backfills.
   Removal is retire-if-pristine. A skills directory without a manifest is a
   legacy install: scan, match against the bundled pack, write the manifest.
   Migration notes ship compiled into the binary keyed by version range
   (zero-fetch posture).
7. **Generated markers stay out-of-band**: manifest enumeration plus
   `.gitattributes linguist-generated`, no content-injected headers, so
   emitted files remain byte-identical to what harnesses expect.
8. **Dev-repo boundary.** The packager never touches this repo's hand-authored
   `.claude/` development content except through the generated cairn-* pack
   paths it owns via the manifest.

## Rationale

Extends dec.init-emits-agent-skills' single-source no-drift invariant from
"this repo's `.claude/skills/` compiled in" to "one canonical source rendered
per harness", so the emitted pack still never drifts from source while gaining
harness coverage beyond Claude. Every mechanism above converged across the
surveyed ecosystems (manifest-at-root, tool-vs-bundle version split,
warn-not-block drift, three-way file handling, vendor/user separation); cairn
already holds the manifest shape at `.agents/.skill-lock.json`.

## Scope boundary

This decision fixes the policy contract only. Exact directory names, manifest
schema, renderer design, and command wiring are implementation scope for the
change directory scaffolded when `todo.agent-pack-implementation` unblocks,
per the normal propose/apply process.
