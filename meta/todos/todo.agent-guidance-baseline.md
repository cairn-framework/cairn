# Agent Guidance Baseline

## Priority

P0. Start now, in parallel with `todo.agent-pack-canonical-foundation`.

## Scope note

This is the programme's single navigation-measurement unit. It absorbs the
navigation family from `todo.blueprint-authorability-eval`, which remains
responsible only for model-authored blueprint, delta, and artefact validity.
One unit owns navigation measurement; do not build a second.

## Question

Measure three distinct claims before changing the shipped guidance:

1. Does Cairn's query surface beat target-only tree and text search?
2. Does the current guidance pack improve use of the same Cairn capabilities?
3. Where is the earliest failed handoff that a smaller router or runbook could
   fix?

## Conditions

- Use two or three pinned-SHA open-source repositories and exact task prompts.
- Pre-register ground-truth files and required facts.
- Split tasks into a visible development set and a sealed confirmation set,
  stratified by repository and task class. Run and analyse only development
  tasks in this todo; the treatment todo first opens the confirmation set.
- Pin immutable target, fixture, Cairn CLI, and pack revisions for every run.
  Execute arms from isolated equivalent states so parallel foundation work
  cannot change the bytes under measurement.
- Hold model, harness, authority, tool budget, external state, and grader
  constant. Randomise paired run order.
- Compare target-only, Cairn CLI/MCP with no guidance pack, and the current
  shipped pack.
- Run three fresh trials per arm as a pilot, then size the final sample from
  observed variance.

## Validity gate

Keep every assigned run in the intention-to-treat primary analysis, including
failures to discover or load guidance. Record availability, retrieval,
invocation, and relevance as fidelity data. Any per-protocol analysis of
engaged runs is secondary. Fix the rubric before runs and blind qualitative
grading to the arm.

## Measures

Grade accepted outcome, claim-matched proof, and architecture/ownership before
cost. Report required-fact recall and precision, calls and tokens to the first
sufficient evidence set, time-to-correct-file, files opened, tool calls, cost,
elapsed time, first-turn/catalog tokens, JIT instruction tokens, tool-result
tokens, and duplicated or irrelevant tokens. Preserve failures and dispersion,
not only averages.

## Acceptance

- Publish only the development corpus, method, raw development run records,
  results, and honest partial-failure cases in a research artefact. Keep the
  confirmation prompts and ground truth sealed until treatment opens them.
- Name the earliest failed handoff for each failure class.
- State small, reversible intervention hypotheses for router, runbook, or
  context changes. Do not implement them in this todo.

## Dependencies

None. `todo.agent-context-bundle` may inventory existing commands in parallel,
but its required-fact scoring waits for this todo's corpus preregistration.
